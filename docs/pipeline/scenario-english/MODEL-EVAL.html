AI Scenario English Trainer — Model Evaluation

Four candidate LLMs benchmarked on the app's three real AI tasks — instant feedback, rubric scoring, and item generation — using the production prompts and Zod contracts. Every number below is measured from live API calls on 2026-06-15; nothing is estimated except clearly-labelled preview prices.

All four candidates produced schema-valid output on every task and all used strict response_format: json_schema successfully — no provider choked on the JSON schema. The decision is therefore about quality, stability, latency and cost, not reliability. Quality leads; cost breaks ties.

Winners are quality-first; the budget/quality alternates cover the opposite end of the trade-off.

Methodology

The harness lives in server/eval/ and reuses the production code paths: prompts from src/ai/prompts.ts and the inline systems in src/scoring/rubric.ts & src/content/generate.ts, validated against the exact Zod schemas in src/schemas.ts (FeedbackPayloadSchema, RubricScoreSchema, ItemGenSchema). No prompts were re-authored.

Same control flow as production runStructured — strict schema first, one repair retry on a validation failure.

Tasks & inputs

  • Instant feedback — 3 fixed learner responses at A2 / B1 / C1, each with deliberate, realistic errors (missing articles, tense, register slips).
  • Rubric scoring — 1 fixed B1 spoken transcript, run 3× per model at temperature 0 to measure scoring stability.
  • Item generation — 1 scenario ("returning faulty headphones"), scenario_translation type, B1.

Where it ran & why

Run locally (macOS). Both providers were reachable from the laptop with no proxy (Gemini HTTP 200, OpenAI HTTP 200 on a key check), and node/tsx were not installed on the BWH box. The OpenAI key was pulled from /opt/scenario-english/.env on the box over SSH and injected into the run's environment only — never written to disk, never committed, masked in all logs. The Gemini key was read from a local file and handled the same way.

Two extra baselines included. The spec's gpt-5.4-mini exists and works, but the OpenAI catalog has no gpt-5-mini sibling at that version — so the closest shipping mini (gpt-5-mini) and flagship (gpt-5.4) were also measured for context. They are shown greyed in the tables and excluded from the headline verdict.

Provider integration findings

handled response_format / json_schema

Every candidate accepted strict response_format: json_schema and returned valid JSON. The harness's "retry-without-schema" fallback was never triggered. No provider choked on the schema.

gotcha temperature rejected

gpt-5.5 (and the baseline gpt-5-mini) return HTTP 400 for any non-default temperature — they only allow the default. The production OpenAIChatClient always sends temperature, so it would fail against these models until it drops the field on a temperature-400.

transient Gemini flash 503s

On the first pass gemini-3-flash-preview returned HTTP 503 "high demand" on 2 calls. A simple 2× backoff retry cleared them; the clean re-run had zero 503s. Worth a retry policy in production for the preview tier.

stable Gemini strict mode

Both Gemini models honoured the OpenAI-compatible strict schema endpoint exactly, including enum-constrained issues[].type. No fence-stripping or repair was needed for any Gemini call.

Action for the backend: add a temperature-400 fallback (drop temperature and retry) and a transient-5xx backoff to OpenAIChatClient before shipping any gpt-5.5-class or Gemini-preview model. The eval harness already implements both as a reference.

Recommendation (quality-first; cost as tiebreaker)

Per-task picks:
  • Instant feedback → gpt-5.4-mini. Feedback quality is a wash with the flagships on these cases (same errors caught, copy-ready phrasing), so the deciding factors are latency and cost — and the mini wins both decisively (~2.5 s, $0.0009/session). Live in-conversation correction needs the latency floor.
  • Rubric scoring → gemini-3.1-pro-preview. Reproducibility is the top requirement here (it feeds progress charts), and it is the only model with zero score drift. If cost becomes a constraint, gpt-5.4-mini (stdev 0.16, ~5× cheaper, 3× faster) is a strong fallback.
  • Item generation → gemini-3-flash-preview. Offline admin pipeline, so latency is irrelevant; it produced rich, idiomatic items at the lowest cost of any candidate and was valid first-try. For maximum editorial polish on flagship items, gemini-3.1-pro is the upgrade.
If the PM wants ONE model for everything: pick gpt-5.4-mini. It was valid first-try on every task, has excellent scoring stability (0.16), the lowest latency, and the lowest cost — the best all-round value. Reserve gemini-3.1-pro for the scoring path only if perfectly deterministic grades are a hard product requirement.
Before shipping any of these: (1) add a temperature-400 fallback to OpenAIChatClient — gpt-5.5-class models reject custom temperatures; (2) add a transient-5xx backoff for Gemini preview tiers (we saw 503s clear on retry); (3) re-confirm preview pricing (marked est.) against the provider contract before locking the budget.
