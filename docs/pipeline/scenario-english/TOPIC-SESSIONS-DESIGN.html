Gate 1 · Design

Topic Sessions — choose what to practise

Let a learner steer a session by topic: quick-pick chips (your existing scenario categories) or a custom free-text topic the app AI-generates a focused session for. The current adaptive feed stays the default; topic is opt-in and per-session. Designed by 3 parallel agents (backend, AI+safety, frontend).

No new setup from you. Moderation reuses the box's existing official OpenAI key (the /moderations endpoint is free on standard keys) — unlike accounts, this needs no new credentials, keys, or DNS.

3. API & data

  • GET /v1/topics — category chips (only categories with ≥1 published item) + a few custom suggestions.
  • POST /v1/study/topic — set the topic on the active session ({kind:'category',category} or {kind:'custom',topic}); custom triggers moderation + generation. GET/DELETE read/clear it.
  • GET /v1/study/next — same shape, now topic-aware: reviews resurface first (global), then the practice pool is narrowed to the topic, then recency-exclusion + adaptive pick. New topic_warming empty sub-state while a custom batch generates.
  • Schema (additive, nullable — safe online migrate): practice_sessions gets topicKind/topicCategory/topicSessionId/topicLabel; new topic_sessions cache table (normalized topic + CEFR + status + moderation); question_items.topicSessionId. Custom topics reuse a synthetic scenario row so every existing join keeps working.

4. Safety (custom free-text) must-have

  • Moderate before generating — OpenAI omni-moderation on the topic; reject inappropriate input (fail-closed, since content is shared).
  • On-domain gate — the AI scaffold flags non-English-practice requests (e.g. "how to build X", "ignore your instructions") → rejected.
  • Prompt-injection hardening — the topic is passed as delimited untrusted data, length-capped, escaped; strict JSON-schema + Zod output means injection can't change output shape or leak the prompt.
  • Quality gate before a generated item is shown/shared (schema + CEFR/difficulty sanity + language checks); failures parked, not served.
  • Rate-limit new-topic generation per user (≈5/10 min, 30/day); cache hits are free. React auto-escapes all rendered text (no XSS).

5. Frontend

  • A slim TopicBar atop Study: default "Today's mix · Adaptive" + a "Choose a topic" button; when active, a topic chip with a clear ×.
  • A TopicPicker sheet: category chips + an "or" divider + a custom text field with example quick-fills.
  • Custom topics show a "Building your {topic} session…" state (Cleo + the existing thinking-dots/skeleton); category chips refetch instantly.
  • Each topic item shows a small provenance badge; due reviews still interleave (review > topic) and keep their review badge.

7. Suggested build order

  1. Curated chips first — category filter on study/next + TopicBar/TopicPicker (chips). Ships half the feature fast, zero AI risk.
  2. Custom AI topics second — moderation + scaffold + generation + cache + the generating state.
  3. QA both (incl. an adversarial safety pass on the custom path), deploy, verify live.
