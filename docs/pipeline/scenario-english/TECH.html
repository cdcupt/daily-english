B5Scoring & CEFR Engine (hybrid, deterministic mapping)

Not one LLM number. Code computes objective speech features; the LLM scores rubric dimensions against fixed anchors; a deterministic function maps to CEFR; a moving average builds the long-term profile.

Scoring pipeline

Audio → (code features ∥ LLM rubric) → aggregate → deterministic scoreToCEFR() → EMA long-term profile (low-confidence turns excluded).

Code-computed speech features (from ASR word timestamps)

rate_wpm        = words / (speech_seconds/60)
pause_ratio     = silent_seconds / total_seconds
repetition_rate = repeated_tokens / total_tokens
asr_confidence  = mean word confidence (see B6)
fluency_raw     = clamp01( w1*norm(rate) - w2*pause_ratio - w3*repetition_rate )

Aggregation

fluency       = 0.6*fluency_code + 0.4*fluency_llm
pronunciation = 0.5*pron_code(intelligibility) + 0.5*pron_llm
total = round( 0.20*vocabulary + 0.20*grammar + 0.18*fluency
             + 0.14*coherence + 0.14*interaction + 0.14*pronunciation )

Deterministic dimension → CEFR band

function scoreToCEFR(s){
  if(s<30)return"A1"; if(s<45)return"A2"; if(s<55)return"A2+";
  if(s<68)return"B1-"; if(s<78)return"B1"; if(s<88)return"B2"; return"C1"; }

Long-term profile (EMA; low-confidence excluded)

for each dimension d with new score x (turn.low_confidence==false only):
  ema_d = 0.3*x + 0.7*ema_d ; n_d += 1
profile.dimensions[d] = { score:round(ema_d), level:scoreToCEFR(ema_d), n:n_d }
overall = scoreToCEFR( weightedMean(ema dims) )
stable_range = [scoreToCEFR(ema-σ), scoreToCEFR(ema+σ)]
Stability guards (PRD risk): temp 0 scoring, in-prompt calibration anchors, deterministic mapping, EMA smoothing, and a golden-set regression test in CI that fails if anchor scores drift.

B7Adaptive Next-Item Engine + Spaced Repetition

The coach picks; the user just shows up. GET /v1/study/next returns one item — a new practice item or a resurfaced review — weighing due reviews, weak dimensions, and coverage against the user's level.

Next-item selection + SM-2 interval ladder

Due review (1-in-N capped) wins; else argmax practice item by weakness/coverage/recency. Ladder: rep 1→1d, 2→3d, then prev·ease; a lapse (grade<3) resets to 1d. 
1. dueReviews = review_tasks where state=pending and due_at <= now
   → if any (cap 1 in N to avoid review-only feeds): return review StudyItem
2. else practice item:
   targetDifficulty = profileScore ± band        // keep ~70–80% success
   candidates = published items near level, difficulty-windowed,
                recency-penalized, preferring a weak-dimension scenario
   score = wWeak*matchesWeakness + wCov*coverageGap - wRecency*recencyPenalty
   return argmax(score)

// SM-2 on review complete with grade q (0–5)
if q<3: reps=0; interval=1d; mastery*=0.6
else:   ease=clamp(ease+(0.1-(5-q)*(0.08+(5-q)*0.02)),1.3,2.8); reps+=1
        interval = reps==1?1d : reps==2?3d : prevInterval*ease
        mastery = min(1, mastery+0.15)
next_review_at = now + interval → spawn review_task at due_at

B9Deployment & Ops (BWH VPS)

A self-contained Docker Compose stack behind Caddy, resource-limited as general good practice so it coexists cleanly with any other tenants on the host. BWH is a candidate host; the app has no dependency on anything else running there.

Deployment topology

BWH host: Caddy → self-contained app containers {api, db, whisper} (cpu/mem-limited); AI/ASR call the official provider API off-host over HTTPS; nightly pg_dump ships off-box.

Services

api (Fastify), db (postgres:16, named volume), optional whisper (faster-whisper). Caddy vhosts: english.daichenlab.com (web, admin at /admin) + api.english.daichenlab.com → api:3000, auto-TLS + B10 headers. DNS via Cloudflare in DNS-only mode (grey cloud) — A records english + api.english → host IP; Caddy obtains Let's Encrypt certs directly (HTTP-01). Matches the user's other apps.

Resource limits

Per-service cpu/memory limits + Postgres shared_buffers cap as general good practice, so the app coexists cleanly with any other tenants. Concurrency cap on AI/ASR to bound spend + CPU.

Backups

Nightly pg_dump → gzip → off-box; 14-day retention; documented restore. Audio blobs on a separate volume, weekly snapshot.

Secrets / env

Host .env (not in repo): DB URL, JWT secrets, provider API key(s) (OPENAI_API_KEY, optional GEMINI_API_KEY), optional self-hosted Whisper URL, Resend key. Boot-time presence check.

F1Client Architecture — Overview

Both render the same three learner surfaces — Study (adaptive feed), You (mirror), Settings — from the same generated types. iOS

SwiftUI, iOS 17+. Reuse TTS, Speech, design tokens, mascot, tab shell. Replace SwiftData-as-source with an API-backed cache + offline write-queue over a generated client.

Shared

OpenAPI 3.1 → openapi-typescript (web) + swift-openapi-generator (iOS), generated in CI. PR fails on drift.

QTest Plan & Acceptance

Concrete, contract-anchored verification for this system. The OpenAPI 3.1 spec is the single source of truth, so the highest-value gates are contract drift, the scoring golden-set (B5 stability), and the full study loop E2E on web + iOS. Tests follow a pyramid (many fast unit, fewer integration, a thin E2E layer) and run in CI on every PR against an ephemeral Postgres with the AI provider and ASR mocked.

Q1. Strategy, pyramid & tooling

Server (Fastify)

Vitest + Supertest against a real ephemeral postgres:16 (Testcontainers / CI service). AI provider + ASR mocked (recorded fixtures + a deterministic fake) so AI/ASR is never hit. Drizzle migrations run before each suite; per-test transaction rollback for isolation.

Web (Next.js)

Vitest + React Testing Library for components/hooks (behaviour over markup); Playwright for E2E + a11y (axe-core) + screenshots. MSW mocks the API for component tests; E2E hits the real server with seeded fixtures.

iOS (SwiftUI)

XCTest (coordinator, cache, write-queue, token store) + XCUITest critical-path on the iPhone 17 Pro simulator. The Mac can build + run iOS, so XCUITest runs in CI/local.

Contract

OpenAPI drift check: regenerate spec from Zod + regenerate web/iOS clients; git diff --exit-code fails the PR (mirrors B9/F4 CI).

Accessibility

axe-core via Playwright on every web surface; XCUITest accessibility audit on iOS. 0 serious/critical violations is a gate.

Performance

Lighthouse CI on Study/You against CWV + bundle budgets (F8); fails the PR on regression past budget.

Coverage target: ≥80% lines/branches on server/src (scoring, adaptive, ai, asr, content, routes, db/repositories) and on web component/hook logic, enforced by the Vitest coverage reporter in CI. Golden-set + contract gates are pass/fail regardless of coverage %.

Q4. Golden-set scoring regression (CI gate — B5 stability guard)

A fixed corpus of recorded transcripts + speech-feature fixtures (spanning A1→C1) with expected dimension scores and CEFR bands within tolerance. The scoring pipeline (code features + a recorded/mocked rubric LLM response replayed via the B4 audit tags) is run and compared.

// server/test/golden/scoring.golden.test.ts
for (const f of fixtures) {
  const report = await scoreSession(f.turns);          // mocked rubric LLM (recorded)
  expect(report.total).toBeCloseTo(f.expected.total, /*±*/ 3);
  for (const d of DIMENSIONS)
    expect(report.dimensions[d].level).toBe(f.expected.dimensions[d].level);
  expect(report.cefr_estimate).toBe(f.expected.cefr_estimate);
}
Gate: any drift beyond tolerance (anchor scores moving, mapping change, prompt-version bump that shifts results) fails CI. This is the PRD "unstable scoring" mitigation made executable. Updating the golden file is a deliberate, reviewed change.
