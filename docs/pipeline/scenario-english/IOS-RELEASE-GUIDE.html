1 Open & archive in Xcode

  1. The project is already generated. Open it:
    open ~/codes/github.com/daily-english/DailyEnglish.xcodeproj
    (If you ever re-clone, run DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodegen generate first — the .xcodeproj is generated, not in git.)
  2. Top device selector → choose Any iOS Device (arm64) (not a simulator).
  3. Select the DailyEnglish target → Signing & Capabilities → confirm Automatically manage signing is on and Team = Chai DaiChen. You should see the Sign in with Apple capability listed. Let Xcode create/download the provisioning profile if prompted.
  4. Menu Product → Archive. Wait for it to build and appear in the Organizer.

2 Upload the build

  1. In the Organizer, select the new archive → Distribute App → App Store Connect → Upload.
  2. Accept the defaults (automatic signing, symbols). Finish the upload.
  3. The build appears in App Store Connect after processing (a few minutes to ~1 hour).

3 App Store Connect — new version 2.0

At appstoreconnect.apple.com → Dailingo:

  1. + Version or Platform → 2.0.
  2. What's New: describe the redesign (scenario practice, accounts, topic sessions, spaced review).
  3. Screenshots: upload fresh ones for the new design (the old ones are the previous app). 6.7" / 6.5" required; you can capture from the simulator.
  4. Build: select the uploaded build (step 2).

4 App Privacy & submit

⚠ Critical — update the App Privacy label. The app now has accounts and collects an email via Sign in with Apple / Google. In App Privacy → Data Collection, declare Contact Info → Email Address (and the user's account identifier), Linked to the user, used for App Functionality. Leaving it as "Data Not Collected" will get the build rejected.
  1. Review notes: note that the app is login-first and reviewers can use Sign in with Apple with their own Apple ID to enter. (No demo credentials needed.)

  3. Add for Review → Submit for Review.
