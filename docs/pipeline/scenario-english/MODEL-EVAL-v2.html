Quality & Error-Rate Benchmark — AI Scenario English Trainer

Four candidate LLMs run through the app's three production AI tasks at scale — 16 instant-feedback inputs, 8 rubric inputs × 3 repeats, 6 item-gen combos — using the live prompts and Zod contracts. Outputs are graded by a fixed, blind LLM-as-judge (gemini-3.1-pro). 184 generation calls + ~88 judge calls, all live on 2026-06-15. Every number is measured; only preview prices are estimated and labelled.

All four models are quality-excellent (judge ≥ 4.88/5 on every task) and order answers correctly 100% of the time. The benchmark separates them on two axes the PM cares about most: reliability (hard-fail %) and scoring stability (run-to-run variance). One model — gemini-3.1-pro — clears every bar on every task; the others each trip one strict gate.

How this was measured

The harness (server/eval/run-v2.ts + dataset-v2.ts) imports the production prompt builders and Zod schemas — nothing is re-authored — and POSTs straight to each provider's /chat/completions with strict response_format: json_schema.

Coverage (N)

Feedback: 16 inputs (CEFR A1–C1; tense, articles, prepositions, word-order, register, naturalness).
Rubric: 8 inputs (weak→strong) × 3 repeats = 24.
Item-gen: 6 scenario×level combos.
= 46 generation calls / model.

Error-rate logic

Each call → valid_first_try, repaired (1 retry feeding the Zod error back), or hard-fail (failed = invalid even after repair, or call_failed = API error after backoff). Error rate = hard-fail %.

Blind LLM-judge

One fixed judge (gemini-3.1-pro, temp 0) scores each output 1–5, blind to which model produced it. Feedback: fixes-errors / naturalness / focus. Item-gen: prompt_cn / references / difficulty. Plus deterministic checks (echo, ≥1 save_candidate, ≤3 issues, phrase coverage).

Provider quirk confirmed live: gpt-5.5 rejects any custom temperature ("Only the default (1) value is supported"), so the harness calls it without the field — the production client must do the same. gpt-5.4-mini and both Gemini models accept custom temperatures normally.
Pass bars (explicit): hard-fail < 2% · mean judge quality ≥ 4.0/5 · worst-case rubric stdev ≤ 3.0 (app-total, 0–100) · ordering-correctness ≥ 90%.

★ Quality-first recommendation, per task

Quality is essentially tied across the field, so the decision is driven by error rate, stability, and the latency/cost the task can tolerate. Recommendations below lead with quality and justify with the measured error rates.

① Instant feedback

gpt-5.4-mini

0.0% hard-fail · 0.0% repair · judge 5.00/5. Fastest (p50 2.0s, p95 3.9s) and cheapest ($0.0004/call) — exactly what a live, high-volume feedback path needs. Quality is indistinguishable from the flagships.

Avoid gemini-3-flash here: its 2.2% hard-fail and 156s p95 tail directly harm the "instant" promise.

② Rubric scoring

gemini-3.1-pro

0.0% hard-fail · worst-case σ 1.96 (only model under the ≤3 bar) · mean σ 0.49 · 100% ordering · judge 5.00 item / strong feedback. Scoring feeds the CEFR estimate, so repeatability outweighs latency/cost here. Pro is the only model a learner can re-run and trust to get the same grade.

Budget alt: gpt-5.4-mini — 0% hard-fail, mean σ 2.46, 100% ordering, 5× cheaper/faster — fine if only relative ranking matters (it does for adaptive selection).

③ Item generation

gemini-3-flash (quality)

Judge 5.00/5 on prompt_cn, references & difficulty — top-tier content at $0.0005/call. But item-gen is an offline admin pipeline with human review, so its 2.2% availability blip and slow tail are tolerable here (retry/queue).

Reliability-first pick: gpt-5.4-mini — judge 4.94, 0% hard-fail, fast/cheap. Use it if the pipeline must run unattended.

If forced to one model for everything: gemini-3.1-pro — it is the only candidate that PASSES every gate on every task (0% error, σ 1.96, 100% ordering, quality ≥ 4.88). The price is latency (p50 10.7s) and ~6× the per-call cost of the mini. For a two-model split that optimizes the product: gpt-5.4-mini for instant feedback + item-gen, gemini-3.1-pro for rubric scoring.
Reliability finding to flag to the PM: the only model that produced a hard error in 184 generation calls was gemini-3-flash-preview (one 503 + multi-second tail spikes). It is a "preview" endpoint and behaved like one under load. Do not put it on a latency-sensitive, user-facing path without a fallback model.
