Gate 1 · Design

Accounts — passwordless email magic-link

Let a learner turn an anonymous device into a real account by email — so progress, expression bank, and CEFR history sync across web + iOS. No passwords. Schema is already account-ready (users.email, email_verified, merged_into). Designed by 4 parallel agents (data-model, adversarial security, email delivery, frontend); this is the design for your sign-off — no code yet.

1. How it works

The link points at the web app (never the API) and only authenticates on an explicit POST — so email scanners that pre-fetch the GET can't burn the one-time token, and the token never leaks via a Referrer header.

2. Anonymous → account (the linking decision)

Decision for you (scope): the security review flagged cross-device data merge as the one genuinely complex/risky part (re-keying 5 tables, dedupe, tombstones, stale-token handling). Attach + Sign-in already delivers your goal — "sync across devices" — because once linked, both web and iOS share one account going forward. Merge only adds the niche case of "I practiced anonymously on a 2nd device before signing in with an existing email." I recommend v1 = Attach + Sign-in, with Merge as a fast-follow.

3. API surface

EndpointPurpose
POST /v1/auth/magic-link/requestSend a link. Optional Bearer = which device to link. Always 200 ("if an account exists, a link was sent") — no email enumeration.
POST /v1/auth/magic-link/verifyConsume token (atomic single-use), run attach/sign-in, issue the normal access+refresh JWTs.
GET /v1/auth/meCurrent identity (anonymous vs linked email) to render the Settings account card.
POST /v1/auth/anonymous · /refreshExisting — minor hardening: follow merged_into, honor token_version.

4. Data

  • New table magic_link_tokens: token_hash (sha256, unique), email, device_user_id (captured server-side at request time — tamper-proof), expires_at, consumed_at, request_ip. One Drizzle migration.
  • users: no change needed for the core flow (email/email_verified/merged_into already exist). Add one column token_version (int) so sign-out/merge invalidates old refresh tokens with a single write.

5. Security — non-negotiables must-have

  • GET never authenticates — the email link opens a web page; auth happens on an explicit POST (defeats inbox scanners).
  • Link → web origin, not API (no token in Referrer/history).
  • Token: crypto.randomBytes(32), stored only as SHA-256, 15-min TTL, single-use via atomic consumed_at IS NULL guard.
  • No enumeration: neutral /request response; one generic /verify error for invalid/expired/used.
  • Device-to-link captured server-side at request time (never trusted from the client at verify) → blocks merge-takeover.
  • Rate limit: 3 / email / 15 min and 5 / IP / 10 min (DB-count guard, no new dependency).
  • token_version invalidates stale refresh tokens on sign-out/merge; requireAuth + /anonymous follow merged_into.

6. Email delivery — the one dependency on you

Provider: Resend (REST via fetch, no SDK — matches the codebase), the product's own key (never 9relay), from a dedicated subdomain login.english.daichenlab.com.

Dev-mode fallback = we can build & ship the whole flow now. With no RESEND_KEY set, the API logs the magic link and (in non-prod) returns it in the response, so login is fully testable end-to-end without any email setup. You add Resend when you want real emails to send.

What you'd provide (later, to enable real emails):

  • A Resend API key (sending-only) → RESEND_KEY=re_… in /opt/scenario-english/.env (never in chat/repo).
  • Verify login.english.daichenlab.com in Resend → add its DKIM/SPF/return-path records in Cloudflare (DNS-only).
  • Confirm sender: Daily English <no-reply@login.english.daichenlab.com>, reply-to support@daichenlab.com.

7. Frontend

  • One new route web/src/app/auth/verify/page.tsx — reads ?token, POSTs verify, stores tokens, redirects home (StrictMode-guarded, Suspense-wrapped).
  • SettingsView: the "Coming soon" stub → real states — email form → "Check your inbox" (with resend cooldown) → "Signed in as {email}" + Sign out. Account card flips Not linked → Linked.
  • Sign-out re-establishes a fresh anonymous session (never tokenless); kept distinct from the destructive "Delete all data".

8. Test plan

  • Unit/integration (vitest): all link cases (attach, sign-in, idempotent), single-use, expiry, enumeration-neutrality, rate-limit, token_version invalidation, merged_into follow.
  • Live E2E from the box (dev-mode email): request → read link from response/log → verify → JWT → confirm sync; security checks (reused GET token, expired token).
  • Web: Playwright at 320/390/1440 of the new Settings states + verify page.
