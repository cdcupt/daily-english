Gate 1 · rev. 2 · OAuth

Accounts — Sign in with Google & Apple

Audience is outside mainland China (the app runs on OpenAI/Gemini, not China-filed), so social sign-in is the best fit. One-tap Google / Apple → verified identity → our normal JWT session → progress, expression bank, and CEFR sync across web + iOS. Replaces the earlier email-magic-link plan; the account plumbing already built is reused.

1. How it works (OpenID Connect)

The provider (Google/Apple) does the identity proof. Our server only verifies the signed ID token against the provider's public keys (JWKS), checks the audience + expiry + that the email is verified, then issues the same JWT every other endpoint already uses.

2. Linking — same idea, keyed on the provider identity

  • Known identity (this Google/Apple account signed in before) → sign in to its account.
  • New identity, anonymous device present → attach: the current device becomes the account; set its email if empty.
  • New identity, email already used (e.g. signed up with Google, now Apple, same verified email) → link the new identity to that existing account.
  • New identity, no device context → create a fresh account.
  • Cross-device sync follows automatically: sign in with the same Google/Apple on web + iOS → one account.

4. Security must-have

  • Verify the ID token signature via the provider's JWKS; check iss, aud (our client / Services ID), exp, and a nonce on web.
  • Only trust email_verified emails for auto-linking by email (Google sets it; Apple emails are verified, may be a private-relay address).
  • token_version invalidates old sessions on sign-out; /refresh enforces it.
  • Provider client IDs / Apple key are config (env) — the private .p8 is a secret, stored on the box only, never in repo/chat.

5. What you provide your part

Google (free, ~5 min, no DNS): a Google Cloud OAuth Client ID (Web) with https://english.daichenlab.com as an authorized origin. (An iOS client ID later for the app.)

For iOS — just the App ID's "Sign in with Apple" capability (native, no Services ID).
