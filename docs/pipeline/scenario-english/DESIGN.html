01 · Design Rationale

Warm editorial coaching, not another gamified tutor

The product is corrective and adaptive — it should feel like a sharp, encouraging editor sitting beside you, not a cartoon classroom. The visual language is warm paper, confident serif headlines against rounded sans body, and color used as meaning: teal acts, coral corrects, violet measures growth. The existing iOS warm palette is the anchor so web and iOS are visibly the same product.

The point of view

Real situations over abstract lessons. Focused correction over error dumps. Retained expression over forgotten vocab. The whole UI is built around one loop — practice, correct, save, review — and every screen earns its place in that loop.

📰 Editorial, not template

Serif display headlines, asymmetric rhythm, a feature-sized "today" card next to smaller tiles. We deliberately avoid the uniform card grid and the centered-hero-with-gradient-blob default.

🧭 Mascots with a job

The existing mascots become scenario-category guides and empty/celebration moments — character, not childishness. They never carry primary navigation.

Final palette

Drawn from Extensions.swift and tuned for WCAG AA on warm paper. Teal/coral/violet are semantic — they never appear decoratively where they would imply the wrong meaning.

Contrast note: iOS appTeal is the brighter #14B8A6 (fine on white fills); web/text teal is the deeper #0D9488 to clear AA on warm paper. Both ship as the same token name in each platform's token layer, so components stay portable.

Type scale & pairing

A two-family strategy: a humanist serif for display/headlines (editorial voice, the "coaching" warmth) paired with the platform rounded sans (SF Pro Rounded on Apple, system-ui elsewhere) for UI and body — matching the existing app's SF Rounded. Hierarchy comes from real scale contrast, not weight alone.

Core components

Signature — 3-tier feedback diff

Never a flat error list. Correction is always a vertical stack: your original (struck, coral) → corrected (neutral, teal label) → natural version (violet). One glance shows the climb from "understood" to "native".

● Your version
I want check in early.
✓ Corrected
I'd like to check in early.
✦ More natural
Would it be possible to check in early?

Component inventory

Shared across web + iOS via the token layer:

Scenario cardMode picker Feedback diffASR retry banner Score ringDimension bars CEFR badgeExpression chip Filter chipTab bar Save toggleLifecycle pill

Surfaces use CardStyle (20px radius, soft shadow) as the base raised surface; recessed surfaces use warm --paper-2.

Motion & interaction principles

Clarify, don't decorate

Motion shows flow: the diff tiers cascade in, the score ring fills. No motion-for-motion's-sake.

Compositor-only

Animate transform & opacity exclusively. 240ms, cubic-bezier(.16,1,.3,1).

Tactile states

Hover lifts/translates; active scales to .97. Every interactive element has a designed press.

Honest loading

Skeletons mirror final layout so AI latency never shifts the page (CLS < 0.1).

Accessibility stance (WCAG 2.2 AA)

ConcernCommitment
ContrastAll text ≥ 4.5:1 (≥ 3:1 large). Color is never the only signal — the diff uses labels + strikethrough + icons, not just hue, so it reads for color-blind users.
Focus statesVisible 3px violet focus ring on every interactive element (web). iOS uses system focus + VoiceOver. No focus is ever suppressed.
Reduced motionprefers-reduced-motion drops all transitions/animations to ~0ms; the ring and diff appear instantly. (Honored live in this very document's mockup.)
Keyboard navFull tab order; mode picker, filters, tabs, and save toggles are real buttons with aria-pressed. Skip-link to main content + to the mockup.
Non-blocking ASR retryLow-confidence audio shows an inline, dismissible coral banner with a Retry action — it never modal-traps the user or discards their turn. The user can accept the draft transcript, retry, or switch to typing.
Voice alternativesEvery voice task has a text fallback. Speaking is never the only path to completing a session (intelligibility scoring is simply skipped).
Targets & copy≥ 44×44px touch targets. CEFR is labeled an estimate everywhere it appears (compliance copy verbatim on the report).
02 · Information Architecture

One product, three navigation models

The existing iOS 6-tab shell (Home · Reading · Writing · Vocabulary · Listening · Me) is retabbed to 5 around the new loop: Home · Scenarios · Practice · Expressions · Profile. Web mirrors the same five as a top nav; the operator Admin is a separate web-only surface behind role auth.

🎓 Learner — shared 5-tab model (web + iOS)

Home          today's pick · continue · weak expressions · quick start
Scenarios     8 categories → list (level/mode filters) → detail
Practice      mode picker → [Translation | Dialogue | Description]
              → live session → AI feedback → Report
Expressions   Vocabulary · Patterns · Mistakes · Saved · Phrases
              → daily Review flow
Profile       long-term CEFR · 6-dimension trends · settings · account

Practice is reachable from Home (quick start), Scenarios (detail → start), and its own tab — the loop never dead-ends. Report is a result of Practice, not a tab; Review lives inside Expressions.

🛠️ Operator — Admin (web only)

Dashboard    bank health · queue size · complaint spikes
Question Bank table: items × lifecycle × quality metrics
             filters: category · level · status · source
             row → detail drawer → approve / archive / re-level
Scenarios    category & scenario coverage map
Sources      content sources + license metadata

Distinct chrome (dark sidebar, dense data tables) signals "back office". Never exposed to learners. Role-gated route segment.

Navigation parity: identical tab labels and order on web + iOS keeps muscle memory portable. The only platform difference is placement — bottom tab bar on iOS/mobile-web, top nav on desktop-web. Filters and the active scenario/tab live in the URL on web (shareable, back-button-correct).

The 8 scenario categories (finalized)

The PRD names four (Daily Life, Travel, Social, Work). We finalize the remaining four below, chosen for high real-world frequency, clear goal/role/phrase structure, and coverage of the four user types without overlapping the first four. Topic Description is treated as a practice mode available within categories plus a dedicated "Express Yourself" pack — not its own category — so categories stay situational.

Rationale for not making "Topic Description" a category by itself: it is a mode (record + post-session review) that applies inside any category, but learners also want a place to just practice speaking at length. "Express Yourself" satisfies both — it surfaces description-style prompts while keeping the other seven categories cleanly situational/dialogic.

04 · Signature Flows

Two flows the whole product hangs on

A · Practice → Report → Save (the core loop)

The user goes from a scenario to a saved expression in one unbroken motion. The 3-tier diff appears at the moment of correction; save-candidates carry straight into the bank.

Pick scenarioHome quick-start or Scenarios → detail → choose mode.
ProduceTranslate / speak a turn / record a description.
Correct (diff)Original → Corrected → Natural, + 1–3 focused issues.
ScoreTotal + 6 dimensions + CEFR estimate + disclaimer.
SaveOne-tap save-candidates → Expressions bank.
Loop"Practice again" or "Review now".

B · Mistake → Review-task generation

A correction isn't just shown — it becomes scheduled, personalized practice. This is the engine behind the P1 review system and the long-term ability profile.

Mistake captured"I want check in early." flagged in a session.
Stored as pairoriginal → corrected → natural, tagged to scenario + weakness.
Tasks generatedUse "I'd like to…"; ask politely with "Would it be possible to…"; re-enter scenario.
ScheduledSpaced repetition sets next-review-at + mastery.
SurfacedHome rail + Expressions daily Review banner.
Mastery updatesKnown/again adjusts mastery → feeds Profile trends.
Why coral leads both flows: the moment of correction is the product's reason to exist. Coral marks it consistently — the struck original, the flagged turn, the retry, the weak-point — so the eye always knows "this is the thing to fix."
